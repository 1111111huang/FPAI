# Per-Match Lesson Reflection — Design

**Date:** 2026-09-11
**Status:** approved, pending implementation plan
**Origin:** direct user request — the single-match lesson path (`agent-train --batch-size 1`, A33's original behavior) and live's per-day lesson groups both currently produce lesson text from a deterministic fill-in-the-blank template (or, for live, a Counter-based stats aggregate), never from the agent's own recorded reasoning. The user wants single-match lessons generated by having an LLM reflect on that match's actual post-match analysis.

## Problem

`generate_lesson_text()` (`src/agent/lessons.py`) is a string template over a `BacktestRecord`'s outcome fields — recommendation, confidence, actual result, market correctness, limitations. It's the default output for every `agent-train --batch-size 1` match and is what a human reviewer sees when deciding whether to approve a lesson. It never looks at *why* the agent reasoned the way it did.

That reasoning already exists: A105–A108 capture each match's full tool-call trace (`reasoning_trace`) into `agent_telemetry`, specifically so it could be analyzed later — but no lesson-generation code reads it back. Even the one LLM-backed reflection that does exist, `generate_batch_reflection()` (used only for `--batch-size N>1` and for live's daily per-day groups), reflects on `recommendation.explanation` — the agent's own *final* summary — not the actual trace of tool calls and evidence it gathered.

Live's daily lessons job has the same gap at a different granularity: it always groups a day's matches by `(competition_id, date)` and runs the batch/stats path, even when a group contains exactly one match.

## Scope decisions (from user)

- **Applies to both agent-train and live.** Train's `--batch-size 1` default path and live's daily per-day grouping both move to per-match reflection. `agent-train --batch-size N>1`'s explicit mini-batch mode (`generate_batch_lesson_text`/`generate_batch_reflection`) is untouched — out of scope.
- **Replaces the deterministic template**, it doesn't sit alongside it. The LLM reflection *is* the lesson text for a reflected match, not an appended narrative.
- **Reflect on every match**, not misses only. Simplicity over cost-shaving; existing `--batch-size`/sampling tooling (`agent-train-experiment` skill) is the lever for controlling volume, not new logic here.
- **Missing `reasoning_trace` → fall back to the existing deterministic template** (`generate_lesson_text`) for that match, unchanged. Pre-A106 records, or any record without captured `full_state`, degrade gracefully rather than producing a broken or LLM-hallucinated lesson.
- **Reflection input is the actual post-match analysis**: the match's own `reasoning_trace` (tool-call trail, already serialized via `serialize_agent_messages`) plus the deterministic outcome facts (recommendation, confidence, actual result, market correctness) as a trustworthy, unhallucinatable anchor — same anchor-then-narrative pattern `generate_batch_reflection` already uses (`stats_text` passed in, never recomputed by the LLM).
- **No external API added.** A live post-match web-search enrichment (Tavily) was considered and explicitly dropped — see "Rejected alternative" below. Structured box-score stats already sitting in ingested data are used instead, for training only (see Architecture).
- **No snapshotting added.** Considered and rejected for the box-score stats specifically: they're a plain read of already-loaded, deterministic local data (see "Rejected alternative"), not a live/non-deterministic call, so there is nothing to cache.
- **Live grouping:** per-match reflection runs for every match inside a day's `(competition_id, date)` group; the group's `lesson_text` becomes those per-match reflections joined together, replacing `generate_batch_lesson_text`/`generate_batch_reflection` at that call site. The DB write shape (one `agent_lessons` row per group) is unchanged.

## Rejected alternative: post-match web search

Initially designed as: an undated Tavily search (`src/agent/tools.py`'s `_web_search_impl`, bypassing the leakage-guarded `_dated_web_search`) run once per match, with results recorded/replayed through `SnapshotStore` (a new `"post_match_search"` tool name, keyed by `match_id` like existing pre-match snapshots) so repeated `agent-train` reruns over the same historical window wouldn't re-pay the Tavily cost.

Dropped in favor of structured post-match stats already available locally (see Architecture) — same qualitative goal (ground the reflection in what actually happened, not just the final score), zero new API dependency, zero new infrastructure. Not pursued further.

## Architecture

### `generate_match_reflection()` — new, `src/agent/lessons.py`

```python
def generate_match_reflection(
    record: Any,                                  # BacktestRecord-shaped
    reasoning_trace: list[dict] | None,            # A106 trace, already-serialized
    llm_invoke: Callable[[str], str] | None,
    match_stats: dict[str, Any] | None = None,     # shots/cards, train-only (see below)
) -> str:
```

- `reasoning_trace` is falsy, or `llm_invoke` is `None` → returns `generate_lesson_text(record)` unchanged. No behavior change for those matches.
- Otherwise: builds a prompt from (a) the deterministic outcome facts — reusing `generate_lesson_text`'s own field access, factored into a small shared helper rather than duplicated — (b) `match_stats` formatted as a grounding line when present (e.g. "Shots: 14-8 (6-3 on target), Cards: 2Y/0R–1Y/1R"), omitted when `None`, (c) the formatted `reasoning_trace`. Asks the LLM for a short reflective lesson: what the agent's own investigation found, whether the miss (if any) traces to a reasoning or evidence gap, one actionable takeaway.
- LLM call raises → falls back to `generate_lesson_text(record)` — same best-effort contract `generate_batch_reflection` already uses elsewhere (never lose the lesson over a transient provider error).

### `match_stats` — new `BacktestRecord` field, train only

Historical rows (`raw_matches`) already carry box-score columns beyond the final score: `hs`/`as` (shots), `hst`/`ast` (shots on target), `hy`/`ay` (yellow cards), `hr`/`ar` (red cards) — standard football-data.co.uk schema, already ingested by `src/ingestion/football_data/loader.py`. `load_outcome()` (`src/agent/backtest.py`) already threads `hc`/`ac` (corners) through with the same pattern.

A new `load_match_stats(row) -> dict | None` helper, same `pd.notna()`-per-field presence check, reads the above columns and returns whichever are present (or `None` — e.g. Sweden-sourced matches have none of these, same as they have no corners today). Set on a new `BacktestRecord.match_stats: dict | None = None` field in `process_match_row`, alongside the existing `actual=load_outcome(row)` call.

Kept deliberately separate from `build_actual_outcome()`'s dict — that dict's contract is "resolvable market outcome" (it's what scores `market_results`); shots/cards aren't a tradeable market, they're reflection grounding only. No change to `build_actual_outcome`.

Live has no equivalent source — `FootballDataClient` only ever fetches `home_goals`/`away_goals` — so live's `match_stats` is always `None`; that section of the prompt is simply omitted there.

### Call site: `main.py:_write_train_artifacts`, `batch_size <= 1` branch

Currently calls `generate_lesson_text(record)` per scored record with no LLM involved. Changes to:
- Build `llm_invoke = _build_llm_invoke(config)` (existing helper, previously only built in the `batch_size > 1` branch — `config` is already passed into `_write_train_artifacts` unconditionally today, just unused here).
- Pass `reasoning_trace=serialize_agent_messages(record.full_state.get("messages", []))` (same call already made for telemetry in `_write_telemetry_rows`) and `match_stats=record.match_stats`.
- Call `generate_match_reflection(...)` in place of `generate_lesson_text(record)`.

### Call site: `app/backend/live_lessons.py:prepare_lesson_batches`

Currently, per `(competition_id, date)` group: builds `records` via `_to_lesson_record`, computes one `generate_batch_lesson_text(records)` stats string, optionally appends one `generate_batch_reflection(records, stats_text, llm_invoke)` call for the whole group.

Changes to: for each outcome in the group, also read `entry.reasoning_trace` off the same `cache.get_latest_any_config(...)` lookup `_to_lesson_record` already performs (already serialized to the same `list[dict]` shape train uses — no reserialization needed), call `generate_match_reflection(record, reasoning_trace, llm_invoke)` per match (`match_stats` omitted — always `None` for live), and join the group's per-match reflections (separated by blank lines, `LIVE_SOURCE_NOTE` prefixed once) into the group's `lesson_text`. `generate_batch_lesson_text`/`generate_batch_reflection` are no longer called from this module; their imports here are removed (both functions remain, and remain used, by `agent-train --batch-size N>1`).

## Testing

New unit tests for `generate_match_reflection` (fake `llm_invoke`, no network):
- Missing `reasoning_trace` or `llm_invoke` → returns exactly `generate_lesson_text(record)`.
- `llm_invoke` raises → falls back to `generate_lesson_text(record)`.
- Happy path → returns the fake LLM's (stripped) output, with and without `match_stats` present, asserting the prompt contains the formatted stats line only when given.

New unit test for `load_match_stats`: present columns → populated dict; all-`NaN` row (Sweden-shaped) → `None`.

Existing tests at both call sites (`main.py`'s agent-train tests, `live_lessons.py`'s tests) that currently assert the old template/batch-stats text get updated to inject a fake `llm_invoke` and assert against the new reflection path instead.

## Non-goals

- `agent-train --batch-size N>1` mini-batch reflection (`generate_batch_lesson_text`/`generate_batch_reflection`) — unchanged.
- Live outcome resolution gaining richer stats (would require a new API — explicitly rejected, see Rejected alternative).
- Any snapshotting of `match_stats` — it's a deterministic local read, nothing to cache (see Scope decisions).

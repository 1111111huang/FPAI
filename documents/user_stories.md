## Phase 16: League-Aware Model Routing & Unknown-Team Cold Start

> Motivated by the web app integration (`documents/app_user_stories.md`). Two gaps found while planning that integration, verified directly against the live code: (1) `ForecastService.forecast_upcoming()`'s league-history branch (`src/forecast/forecast_service.py:314-429`) never consults `config/competitions.yaml` — it unconditionally loads the flat `"league"` model context regardless of what `league` string is passed, so a non-EPL fixture doesn't cleanly fall back to `general_purpose`, it silently gets a cold-start-heavy forecast mislabeled `prediction_basis: "team_history_and_market"`. (2) Today's cold-start imputation (US#59) handles missing *feature values* for teams that exist in `raw_matches`; it has no concept of a team that has *zero* rows at all (e.g. newly promoted, or a team from a league never ingested).

## Phase 20: Sweden Allsvenskan as a Second Competition

> Picked 2026-07-20 after live-verifying football-data.co.uk's actual coverage (not just the EPL-scraper code, which only pointed at `englandm.php`): the site has a "New Leagues" section (`football-data.co.uk/new/<CODE>.csv`) covering Sweden, Norway, Finland, Denmark, and Ireland among others. >
> **Critical difference from EPL, verified against the live CSV, not assumed:** the "New Leagues" format is a single combined-history file per country with columns `Country,League,Season,Date,Time,Home,Away,HG,AG,Res,PSCH,PSCD,PSCA,MaxCH,MaxCD,MaxCA,AvgCH,AvgCD,AvgCA,BFECH,BFECD,BFECA,B365CH,B365CD,B365CA` — goals and five bookmakers' *closing* 1X2 odds only. **No shots, shots-on-target, corners, cards, over/under-2.5, or Asian-handicap columns at all.** This rules out `home_corners`/`away_corners`/`total_corners` as trainable targets (no source data, not even cold-startable), `DIS_*` features, and the `MKT_AH_*`/`MKT_IMPLIED_OVER25`/`MKT_IMPLIED_UNDER25`/`MKT_LAMBDA_*` feature family (all need O/U-2.5 or AH odds this source doesn't have). >
> Depends on **US#110** (Phase 18a, completed 2026-07-19) — Sweden is a second `competition_specific` competition and hits the exact same flat `league`/`international` model-context binary MLS would have.
>
> **Scope expanded 2026-07-20**: the end product must be CLI-testable, callable by the agent's tool layer (MCP), and — new requirement — the data pipeline must feed **both** the Sweden-specific model and the general-purpose (market-odds-only) model, not just the former. This pass also audited the codebase specifically for risks that would recur on a *third* competition, since Sweden is the first time any code path here has had to handle more than one non-`international` value. Three real findings, all confirmed by reading the actual code (not inferred):
> 1. **`generate_match_id(date, home_team, away_team)`** (`src/utils/helpers.py:13`) hashes only date + team names — **no league component at all**. Two different competitions with a match on the same date between similarly-named teams would produce an identical `match_id`, and since `match_id` is the dedup/join key used throughout (`raw_matches`, `feature_store`, forecast payloads), a collision would silently merge two unrelated matches from different leagues. This was never exercisable with only E0 in the system. **Fixed 2026-07-20 — see US#140.**
> 2. **`model_tools.get_model_status()`** (`src/tools/model_tools.py:28`) hardcodes `for ctx in ["league", "international"]` and its docstring says the return dict has exactly keys `'league'` and `'international'`. This is the same flat-binary problem US#110 fixes in `forecast_service.py`, but it's a **separate hardcoded assumption in the agent-tool layer** that US#110 alone will not fix — the agent's `model_status` tool would silently never show Sweden. **See US#136 (Phase 20d).**
> 3. **`TeamNameMapper.map_team()`** (`src/ingestion/common/team_mapping.py:79`) has no league parameter — it fuzzy-matches (Levenshtein, `min_similarity=0.82`) against the single flat `config/team_mapping.json` namespace regardless of which competition is being ingested. Not a confirmed bug with only Sweden + England in play (no known name collision today), but structurally unscoped — a third or fourth country with a similarly-named club is a real future collision risk, not just a hypothetical one. **Reviewed and partially fixed 2026-07-20 — see US#141.**
>
> A fourth candidate risk — MLflow experiment names (`FPAI_<target>_<model_family>_<sweep_stage>_<version>`) not including league, so Sweden's and EPL's sweep runs land in the same experiment — turned out to be **already handled**: `model_comparison.py`'s `get_runs_by_target(..., context=...)` already filters by the `tags.context` MLflow tag and isn't hardcoded to two values. The residual risk is purely ergonomic (the filter is optional and defaults to unfiltered), not a structural bug, so it gets a lighter-weight story than the other three (US#142).

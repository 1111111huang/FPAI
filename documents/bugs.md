# FPAI Bug Tracker

This document tracks bugs and issues discovered during development and testing. Default status is `open`.

| Bug ID | Title | Description | Status | Notes |
| :--- | :--- | :--- | :--- | :--- |
| BUG-001 | Missing xG and LUCK features blocking training | Feature factory generates xG and LUCK features derived from xG data (luck = fthg - xg_h), but raw_matches table had no xG data initially. When xG is missing, these features become NaN and are stored as string "nan" in DuckDB, causing all training rows to be dropped during dropna(). | fixed | Removed xG_R3/R5, XGA_R3/R5, LUCK_R3/R5 features from schema.yaml selected_features. These will be re-added once Understat integration provides xG data. |
| BUG-002 | Schema.yaml included unsupported features dependent on missing data | Configuration referenced 28 features (xG, XGA, LUCK variants) that cannot be generated without source xG data from ingestion. | fixed | Feature set reduced from 92 available features to 62 data-complete features. Updated config/schema.yaml to remove xG/LUCK-dependent features. |
| BUG-003 | Sklearn mean_squared_error squared parameter compatibility | Regression model evaluation failed: `mean_squared_error(..., squared=False)` threw TypeError about unexpected keyword argument. The sklearn API differs across versions. | fixed | Changed to compute MSE first, then apply np.sqrt() for RMSE. This is compatible across sklearn versions. |
| BUG-004 | Model comparison missed split metrics with suffix-style names | MLflow runs could log metrics as `log_loss_test` while comparison expected `test_log_loss`, causing incomplete comparison reports. | fixed | `ModelComparison.extract_metrics_for_run()` now normalizes both prefix and suffix split metric styles. |
| BUG-005 | XGBoost classifier failed on string multiclass labels | `result_3way` uses labels such as `home`, `draw`, and `away`; XGBoost expected integer class IDs and failed during smoke sweep training. | fixed | `XGBoostModel` now label-encodes classifier labels during training and inverse-transforms predictions. Loss evaluation reads the wrapper class order. |
| BUG-006 | XGBoost multiclass sweep used binary logloss defaults | A multiclass smoke sweep failed because XGBoost received a binary `logloss` evaluation metric for `result_3way`. | fixed | `SweepRunner` now sets task-aware XGBoost objectives/metrics: `multi:softprob`/`mlogloss` for multiclass and `binary:logistic`/`logloss` for binary. |
| BUG-007 | Local MLflow file store has malformed experiment directories | CLI and experiment runs repeatedly warn that `mlruns/1` through several local experiment folders are missing `meta.yaml`. Runs still complete, but logging is noisy and slower. | fixed | Implemented `cleanup-mlflow` CLI command (user story 50) to repair malformed experiments. Successfully recovered 9 malformed experiments by creating minimal meta.yaml files. |
| BUG-010 | League context missing from model_selection.yaml | `config/model_selection.yaml` only contains an `international` context. When `forecast_league` is called, `ForecastService` previously fell back to the international MKT-only models (13 features) but the feature factory generates 142 league features, causing an XGBoost `feature_names mismatch` crash. Partial fix applied: `_load_context_models` now returns empty dict for missing contexts (no glob fallback), so `forecast_league` returns a clean error JSON. | fixed | Full fix (2026-06-27, agent A19): trained all 8 targets with `train-target --model xgb/xgb_regressor --context league` (plain `train-forecast-suite` defaults to `lr`/`rf_regressor`, which crash with "No rows left" since 12 xG/LUCK columns are 100% NaN — XGBoost tolerates NaN natively, non-XGBoost models don't). Found and fixed two latent bugs in the selection pipeline along the way: (1) `run_train_target`/`ModelManager` never tagged `context`/`sweep_stage` on plain (non-sweep) runs, so `select-best-models` could never find them — fixed by tagging both inside `ModelManager.run_pipeline()`. (2) `ModelSelector` constructed `model_path` from the MLflow autolog artifact URI (`.../artifacts/model`, an MLflow-flavor directory), which `ForecastService` can't `joblib.load()` — fixed by logging an `artifact_filename` param and pointing `model_path` at the actual `models/*.joblib` file. `forecast_league` now returns `data_quality.prediction_basis == "team_history_and_market"` for E0 matches, verified via a live spot-check. |

| BUG-009 | Over/under 2.5 goals and Asian handicap odds not ingested from source CSVs | Football-data.co.uk CSVs contain over/under 2.5 goals odds (`Avg>2.5`, `Avg<2.5`) and Asian handicap odds (`AHh`, `AvgAHH`, `AvgAHA`) which are the market's direct signal for goals and match outcome. These columns are present in all E0 CSVs but are never stored in `raw_matches` or derived into features. Only `Avg>2.5` is read from the CSV solely for Pydantic validation and then discarded. The market implied probability for over/under 2.5 goals is arguably the single strongest predictor for goals targets and was confirmed absent from feature importance analysis. | fixed | Added `over25_odds`, `under25_odds`, `ah_line`, `ah_home_odds`, `ah_away_odds` columns to `raw_matches`. Extended `data_loader.py` to ingest them. Added `MKT_IMPLIED_OVER25`, `MKT_IMPLIED_UNDER25`, `MKT_AH_LINE`, `MKT_AH_HOME_ODDS`, `MKT_AH_AWAY_ODDS` features in `feature_factory.py`. Updated `config/schema.yaml` selected_features. |
| BUG-011 | SnapshotStore mode/match_id never reached tool-execution thread — record and replay silently behaved as live | `SnapshotStore` (A09) stores `mode`/`match_id`/`match_date` in `threading.local()`. LangGraph's `ToolNode` executes every tool call — even a single one — via `langchain_core.runnables.config.get_executor_for_config()`, which returns a `ContextThreadPoolExecutor`. That executor runs the tool call on a *different* OS thread than the one that called `configure_snapshot_store()`. `ContextThreadPoolExecutor` explicitly copies `contextvars.Context` into its worker (`copy_context().run(...)`), but never touches `threading.local()`, which is strictly per-OS-thread. So the worker thread's `SnapshotStore._local` was always a fresh, uninitialized `threading.local()`, and `mode` silently defaulted to `"live"` regardless of what the calling thread had configured. Effect: `agent-snapshot` ("record" mode) called the real `ForecastService`/Tavily every time but never wrote a snapshot file — every match still got a `_complete.json` marker and printed "OK" because the live call succeeded; `agent-backtest` ("replay" mode) never read a recorded file either, so it silently made fresh live calls and never once raised `SnapshotMissingError`, even though the snapshot corpus on disk was entirely empty (24 directories containing only `_complete.json`, zero tool-response files). This also disabled the `before:<date>` web_search leakage filter (gated on `mode in ("record", "replay")`), since mode always read as `"live"`. Caught because the user manually inspected `data/agent_snapshots/` and found zero tool-call files despite 24/24 "successful" runs — no automated test caught it because all existing `SnapshotStore`/tool tests call `configure_snapshot_store()` and the tool function on the *same* thread, never exercising the real `ToolNode` dispatch path. | fixed | Switched `SnapshotStore` from `threading.local()` to `contextvars.ContextVar` (`src/agent/snapshot_store.py`) — `ContextThreadPoolExecutor` and `asyncio.to_thread` (used by `agent-backtest --concurrency`) both explicitly propagate `contextvars.Context` into worker threads, while a bare `threading.Thread()` (not used anywhere in this codebase) still correctly does *not* inherit it, preserving the cross-match isolation A09/A14 need. Proven via: an isolated repro showing `threading.local()` fails and `contextvars.ContextVar` succeeds across a real `ContextThreadPoolExecutor`; a new regression test `test_mode_and_match_propagate_into_context_thread_pool_executor`; a live single-match `agent-snapshot` run showing real `forecast_league_*.json`/`web_search_*.json` files now appear with `before:2026-03-16` correctly appended to the search query; and a canary-injection test that doctored a recorded `forecast_league` response and confirmed `agent-backtest` replay returned the doctored content rather than a fresh live forecast. Entire A20/A21 pilot corpus and both backtest reports were discarded and re-collected/re-run after the fix — see `agent_techspec.md` Section 18 for the corrected baseline. |

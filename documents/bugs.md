| BUG-011 | SnapshotStore mode/match_id never reached tool-execution thread — record and replay silently behaved as live | `SnapshotStore` (A09) stores `mode`/`match_id`/`match_date` in `threading.local()`. LangGraph's `ToolNode` executes every tool call — even a single one — via `langchain_core.runnables.config.get_executor_for_config()`, which returns a `ContextThreadPoolExecutor`. That executor runs the tool call on a *different* OS thread than the one that called `configure_snapshot_store()`. `ContextThreadPoolExecutor` explicitly copies `contextvars.Context` into its worker (`copy_context().run(...)`), but never touches `threading.local()`, which is strictly per-OS-thread. So the worker thread's `SnapshotStore._local` was always a fresh, uninitialized `threading.local()`, and `mode` silently defaulted to `"live"` regardless of what the calling thread had configured. Effect: `agent-snapshot` ("record" mode) called the real `ForecastService`/Tavily every time but never wrote a snapshot file — every match still got a `_complete.json` marker and printed "OK" because the live call succeeded; `agent-backtest` ("replay" mode) never read a recorded file either, so it silently made fresh live calls and never once raised `SnapshotMissingError`, even though the snapshot corpus on disk was entirely empty (24 directories containing only `_complete.json`, zero tool-response files). This also disabled the `before:<date>` web_search leakage filter (gated on `mode in ("record", "replay")`), since mode always read as `"live"`. Caught because the user manually inspected `data/agent_snapshots/` and found zero tool-call files despite 24/24 "successful" runs — no automated test caught it because all existing `SnapshotStore`/tool tests call `configure_snapshot_store()` and the tool function on the *same* thread, never exercising the real `ToolNode` dispatch path. | fixed | Switched `SnapshotStore` from `threading.local()` to `contextvars.ContextVar` (`src/agent/snapshot_store.py`) — `ContextThreadPoolExecutor` and `asyncio.to_thread` (used by `agent-backtest --concurrency`) both explicitly propagate `contextvars.Context` into worker threads, while a bare `threading.Thread()` (not used anywhere in this codebase) still correctly does *not* inherit it, preserving the cross-match isolation A09/A14 need. Proven via: an isolated repro showing `threading.local()` fails and `contextvars.ContextVar` succeeds across a real `ContextThreadPoolExecutor`; a new regression test `test_mode_and_match_propagate_into_context_thread_pool_executor`; a live single-match `agent-snapshot` run showing real `forecast_league_*.json`/`web_search_*.json` files now appear with `before:2026-03-16` correctly appended to the search query; and a canary-injection test that doctored a recorded `forecast_league` response and confirmed `agent-backtest` replay returned the doctored content rather than a fresh live forecast.
